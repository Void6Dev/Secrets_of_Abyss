# Инструкции для Claude Code — Terraria Mod

## Общие принципы работы

### Эффективность токенов
- Читай только те файлы, которые **непосредственно нужны** для задачи. Не открывай файл "на всякий случай".
- Прежде чем читать файл целиком — используй `grep`/`find` чтобы убедиться, что нужное там есть.
- Не повторяй в ответе большие блоки кода, если изменение минимально — показывай только diff или изменённый участок.
- Если задача большая — сначала уточни план одним коротким сообщением, и только после подтверждения приступай.

### Остановка при неуверенности
- Если в процессе размышления возникает неопределённость (поведение tML API, порядок вызовов хуков, совместимость с другими модами) — **немедленно прекрати** и сообщи о проблеме, не продолжай генерировать потенциально неверный код.
- Формат сообщения о проблеме:
  ```
  ⚠️ Возможная проблема: [описание неопределённости]
  Нужно уточнить: [конкретный вопрос]
  ```
- Лучше остановиться и спросить, чем реализовать что-то, что сломает мод.

## Правила написания кода

### Читабельность
- Именуй переменные и методы описательно: `projectileSpeedMultiplier` вместо `psm`, `OnHitEnemy` вместо `Hit`.
- Каждый нетривиальный блок логики НЕ нужно сопровождать комментарием, только важное, переменные ли работу. 
- Константы выноси в `const` или `static readonly` с понятным именем, не хардкодь магические числа.
- Группируй поля класса: сначала константы, затем поля состояния, затем свойства.

### Унификация — не переизобретай колесо
- **Перед написанием нового метода** — поищи в проекте уже существующий через `grep -r "имяМетода" .`
- Если похожая логика уже есть в другом файле проекта — **вынеси её в общий хелпер** (например `Common/Utils/ModHelpers.cs` или аналогичный) и используй оттуда.
- Не дублируй: утилиты для урона, формулы масштабирования, проверки условий (boss alive, hardmode, etc.) должны существовать в одном месте.
- Если обнаружен дубликат логики в существующем коде — предложи рефакторинг, но не делай его без явного запроса.

### Механики Terraria — подсказки
- При реализации эффектов всегда учитывай контекст: `Main.netMode` (одиночная / сервер / клиент).
- Для синхронизации в мультиплеере используй `NetMessage.SendData` или `ModPacket`.
- Хуки жизненного цикла: `SetDefaults` → `SetStaticDefaults` → `AddRecipes`. Не путай порядок.
- Для кастомного AI снарядов/NPC всегда проверяй, не перекрывает ли `aiStyle` базовое поведение.
- `ModPlayer` хуки (`PreUpdate`, `PostUpdate`, `OnHurt` и др.) — предпочтительное место для эффектов на игрока.
- При работе с тайлами не забывай про `TileID.Sets` и `Main.tileSolid[]` для корректной физики.

## Рабочий процесс

1. **Получил задачу** → кратко опиши, что собираешься сделать (1–3 предложения). Жди подтверждения если задача нетривиальная.
2. **Перед написанием кода** → проверь проект на наличие похожей реализации (`grep`).
3. **Пишешь код** → следуй правилам читабельности и унификации выше.
4. **Неуверен** → останавливайся и сообщаешь о проблеме (см. выше).
5. **После изменений** → кратко перечисли что изменено и почему.

## Чего не делать

- ❌ Не читай весь проект при каждом запросе — только релевантные файлы.
- ❌ Не генерируй "рыбу" с TODO внутри без предупреждения.
- ❌ Не копируй логику из одного файла в другой — выноси в общий хелпер.
- ❌ Не используй `Main.player[Main.myPlayer]` на стороне сервера.
- ❌ Не игнорируй netcode если добавляешь визуальные эффекты или изменения статов.
